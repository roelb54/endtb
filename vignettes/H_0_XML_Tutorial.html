TBVax model specification

A TBvax model is specified by an XML document. The type of XML document used for TBvax is formally specified in an XML Schema: TB-Vx-schema-[#].xsd where [#] is the version of the XML Schema. The current XML Schema is TB-Vx-schema-Z.xsd

The XML Schema specifies:

  • additional data types (e.g. fraction, a double between 0.0 and 1.0 inclusive)
  • the structure of the XML document (i.e. the order and hierarchy of XML elements)
  • XML attributes
  • referential integrity (e.g. if an age group is referred to in a parameter definition, the value of the age group is checked for validity)

See https://www.w3schools.com/xml/schema_intro.asp for background information about XML Schema.

The overall structure of an XML document that specifies a TBvax model is as follows:

<TB.Vx.model.inputfile>
  <simulation/>
  <output/>
  <ages/>
  <VXa/>
  <SES/>
  <RISK/>
  <HIV/>
  <TB/>
</TB.Vx.model.inputfile>

The <simulation> and <output> elements contain details about running the model and about the output to be generated, not about the model itself (i.e. model dimensions, transitions between states, disease transmission etc.).

In the following sections we will document the <simulation> and <output> elements, the definition of age groups using with <ages>. The use of the <VXa>, <SES>, <RISK>, <HIV> and <TB> elements is illustrated with example model specifications of increasing complexity:

The <simulation> element

The <simulation> element attributes from.year and thru.year specify the start and the end of the simulation run [note that thru.year is the final time point i.e. 2021.0 in this case] ; dt is the time step for generating output.

 <simulation from.year="2020" thru.year="2021" dt="0.02">
  <options>
   <numerical.integration method="ode45" atol="0" rtol="1e-7" min.value.for.state.var="-0.1"/>
   <intervention.start from.incidence.data="VXa"/>
  </options>
  <demography country.code="ignored" rescale.population="1950">
   <from.data>
    <population file="data/demographics.csv"/>
     <birthrate from.population.data="true"/>
     <mortality file="data/deathrates.csv"/>
    </from.data>
  </demography>
  <contact.matrix file="data/all_contacts_2020.txt"/>
 </simulation>

The <numerical.integration> element is defined as follows in the XML Schema :

  <xs:element name="numerical.integration">
    <xs:complexType>
      <xs:attribute name="from.year" default="1900" type="xs:integer"/>
      <xs:attribute name="method" default="ode23" type="rkMethod"/>
      <xs:attribute name="maxsteps" default="5000" type="xs:nonNegativeInteger"/>
      <xs:attribute name="hmin" default="0.0" type="fraction"/>
      <xs:attribute name="hini" default="0.2" type="fraction"/>
      <xs:attribute name="rtol" default="1e-6" type="fraction"/>
      <xs:attribute name="atol" default="1e-6" type="fraction"/>
      <xs:attribute name="min.value.for.state.var" default="-0.03" type="xs:double"/>
    </xs:complexType>
  </xs:element>

which means that the XML element <numerical.integration> has attributes and default values as listed above.

The attributes method, maxsteps, hmin, hini, rtol and atol are passed to the deSolve rk() function unchanged.

The attribute from.year can be used to switch the numerical integration method at any time during the simulation run. In that case two <numerical.integration> elements are required, one with e.g. from.year="1900" and another with from.year=2025 to switch in 2025 to a numerical integration algorithm with e.g. higher precision.

The attribute min.value.for.state.var sets the minimum value for any state variable. Negative values of state variables should not occur but are often inevitable. Any negative value is reported in the log file and values more negative than ’min.value.for.state.var` cause the simulation to stop with an error message.

The simplest specification of <numerical.integration> would be an empty element i.e. <numerical.integration/> as all attributes have sensible defaults.

The <simulation><options><intervention.start> element is used for comparing intervention and baseline runs and is defined as follows in the XML Schema :

  <xs:element name="intervention.start">
    <xs:complexType>
      <xs:attribute name="from.incidence.data" default="VXa" type="xs:string" />
      <xs:attribute name="year" default="1e6" type="nonnegdouble"/>
    </xs:complexType>
  </xs:element>

which means that the start of the intervention is either derived from the incidence data (a file that specifies e.g. a vaccine intervention) or by the specified year.

For baseline runs, the element <intervention.start> can be omitted as it is an optional element.

The minimal contents of the <simulation><options> element would be:

  <options>
   <numerical.integration/>
  </options>

The <simulation><demography> element has attributes country.code and rescale.population. Usually country.code="ignored" meaning the the ISO3 country code is derived from the argument passed to the set.paths() function which is called to set up a simulation run. rescale.population is a required attribute without default ; it specifies the year when the age distribution of the population is rescaled to the initial age distribution (i.e. as specified for the first simulation year). Usually, the population is adjusted to the demographics data (UNPOP data) every year ; in that case it is preferred to set to a year past the end year of the simulation with e.g. rescale.population="2200"

The <simulation><demography> element has three subelements:

  <birthrate from.population.data="true"/>
  <mortality file="data/deathrates.csv"/>
 </demography>

The file attribute of <population> should point to a file with UNPOP projections i.e. population by single year age groups from 1900 - 2050. The file location is relative to the folder with the ISO3 country code e.g. ZAF/data/demographics.csv where ZAF is the ISO3 country code of South Africa.

The from.population.data attribute of <birthrate> means that the number of newborns will be derived from UNPOP data ; in this model version the value should be "true"

The file attribute of <mortality> should contain UNPOP mortality data (e.g. "data/deathrates.csv") and is used to calculate background mortality.

The <contact.matrix> element above has a file attribute pointing to a file with contacts between contactors in rows and contactees in columns speficied by 5 year age groups, and based on data from the Polymod study (Kiesha Prem et al., https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1009098 ).

As with other files, the country code will be prepended to the file name e.g. ZAF/data/ZAF_all_contacts_2021.txt. If the <contact.matrix> element is omitted / commented out, age mixing will be proportionate.

The <output> element

  <output>
   <detailed.output years="2020+(0:50)*0.02" age.group.lower.limits="c(0,15)">
      <flows dim="TB" transmission="true" progression="true"/>
      <flows dim="HIV"/>
      <flows dim="VXa"/>
      <flows dim="RISK"/>
    </detailed.output>
  </output>

The value of the years attribute "2020+(0:50)\*0.02" means that output will be generated from 2020.0 thru 2021.0 in time steps of 0.02 years; all output time points should be in the specified simulation years, e.g. with <simulation from.year="2020" thru.year="2021" dt="0.02"\> The value of age.group.lower.limits should be a subset of age groups specified in <ages>. Further optional attributes of the <detailed.output> element are "econ.output","suppress.zeros.in.stocks", "suppress.zeros.in.flows", "combine.stocks.and.flows" which are all "false" by default and can be enabled by setting the attribute value to "true".

The <flows> elements have attribute dim to specify the dimension to generate output for, and optional attributes transmission, progression, treatment and incidence which determine which output to generate ; the value of these attributes is "false" by default and should be set to "true" to enable that type of output.

Model dimensions

A TBvax model has six dimensions that are specified in the <ages>,<VXa>,<SES>,<RISK>,<HIV>, and <TB> XML elements.
The number of state variables in a TBvax model is equal to the multiplication of the number of state variables for each dimensions e.g. 82 age groups * 2 SES classes * 10 HIV states * 12 TB states = 19680.

Age group definition with <ages>

Currently there are two options for specifying the age groups in the model:

  <ages lower.limits="c(0:80,90)"/>

the lower limits are specified using R syntax ; the expression c(0:80,90) above expands to 0,1,2,…80,90 i.e. single year age groups 0 thru 79, one age group 80-89, one age group 90-99.

  <ages lower.limits="5*(0:15)"/>

the lower limits specified above are 0,5,10,15,…75 i.e. 5 year age groups 0-4, 5-9, etc and one 75-99 age group

In the remainder of this document we will use examples to illustrate the use of the <VXa>,<SES>,<RISK>,<HIV>, and <TB> XML elements.

We will start with a simple SIR model specification (without VXa, SES, RISK and HIV dimensions enabled) and continue with specification of increasing complexity.

A simple SIR model specification

The TBvax model is generic as it is completely flexible in defining the natural history and transmission of the infectious disease studied.

In this SIR example the infectious disease is of course not Mtb but some other airborne infectious disease such as SARS-CoV-2.

<?xml version="1.0" encoding="UTF-8"?>
<TB.Vx.model.inputfile xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:noNamespaceSchemaLocation="../../TB-Vx-schema-Z.xsd">

Run from 2020 thru 2021 with time steps of 0.02 year:

  <simulation from.year="2020" thru.year="2021" dt="0.02">

Use UNPOP data for population age composition and death rates:

    <options><numerical.integration/></options>
    <demography country.code="ignored" rescale.population="2050">
      <from.data>
        <population file="data/demographics.csv"/>
        <birthrate from.population.data="true"/>
        <mortality file="data/deathrates.csv"/>
      </from.data>
    </demography>
   </simulation>

Generate output for every 0.02 year time step from 2020 thru 2021.0, use age groups 0 thru 14 and 15 thru 99 (output for 0 thru 99 will be generated by default) and generate flows output for transmission and progression:

  <output>
   <detailed.output years="2020+(0:50)*0.02" age.group.lower.limits="c(0,15)">
      <flows dim="TB" transmission="true" progression="true"/>
      <flows dim="HIV"/>
      <flows dim="VXa"/>
      <flows dim="RISK"/>
    </detailed.output>
  </output>

We will use 5 year age groups:

<ages lower.limits="5\*(0:15)"/>

The VXa, SES, RISK, and HIV dimensions are not used in this example:

<VXa> <VXa.stages> <stage name="NA"/></VXa.stages></VXa>
<SES> <SES.stages> <stage name="NA"/></SES.stages></SES>
<RISK><RISK.stages><stage name="NA"/></RISK.stages></RISK>
<HIV> <HIV.stages> <stage name="NA"/></HIV.stages></HIV>

Define the S, I and R stages:

<TB>
 <TB.stages>
  <stage name="S" />
  <stage name="I" />
  <stage name="R" />
 </TB.stages>

and start with start with 1% infected in 2020:

<seeded.infections name="multiplier" value="1">
<seeded.infection fraction="0.01" age.from="0" age.thru="99" stage="I"/>
<seeded.infection fraction="0" age.from="0" age.thru="99" stage="R"/>
</seeded.infections>

Define

  • TB progression from I to R i.e. transitions independent of transmission

  • parameter d i.e. duration of the I stage which is 7 days

  • the rate of the transition from I to R as 1/(d/365.2425)

Note that all rates have the unit 1/year ; one year is defined as 365.2425 days

<TB.progression>
 <TB.parameter name="d" value="7" />
 <transition.matrix>
  <transition from="I" to="R" rate="1/(d/365.2425)" />
 </transition.matrix>
</TB.progression>

Define the infectivity of the I stage of the “drugsens” Mtb-strain to be 1.0:

<TB.infectivity >
 <TB.parameter name="infc" value="1." /> 
 <infectivity.matrix Mtb-strain="drugsens">
  <infectivity stage="I" value="infc" />
 </infectivity.matrix>
</TB.infectivity>

Set parameter bc to 0.4 ; bc is the product of transmission probability per contact and contact rate. Note that the contact rate is per day as Polymod matrices have contacts per day ; internally the contact rate is multiplied with 365.2425 days/year to be consistent with year as the time unit. The R0 equals bc*365.2425*d/365.2425 = bc*d

<TB.transmission>
 <TB.parameter name="bc" value="0.4" />
 <transmission.matrix Mtb-strain="drugsens">
  <transition from="S" to="I" rate="bc" />
 </transmission.matrix>
</TB.transmission>

An SEIR model with two SES states

To extend the simple SIR model to an SEIR model with two SES states and an increased disease duration and infectivity in the ‘low’ SES class we need to modify the XML specification as follows.

First, define the two SES states:

<SES> 
 <SES.stages> 
  <stage name="high" fraction.at.birth="0.6"/>
  <stage name="low"  fraction.at.birth="0.4"/>
 </SES.stages>
</SES>

Add the E disease stage, and set the initial fraction E to 0 (keep I at 1%)

<TB.stages>
 <stage name="S" />
 <stage name="E" />
 <stage name="I" />
 <stage name="R" />
</TB.stages>
<seeded.infections name="multiplier" value="1">
<seeded.infection fraction="0.01" age.from="0" age.thru="99" stage="I"/>
<seeded.infection fraction="0" age.from="0" age.thru="99" stage="E"/>
<seeded.infection fraction="0" age.from="0" age.thru="99" stage="R"/>
</seeded.infections>

Set the duration of E to 5 days and make parameter d (duration of the I stage) dependent on SES by specifying the SES.stage attribute of the TB.parameter d ; for low SES d=14 days whereas for high SES d=7 days:

The transition rate from E to I is equivalent to a duration of E of 5 days.

<TB.progression>
  <TB.parameter name="dexposed" value="5" />
  <!-- duration of infectious stage depends on SES-->
  <TB.parameter SES.stage="low"  name="d" value="14" />
  <TB.parameter SES.stage="high" name="d" value="7" />
  <transition.matrix>
   <transition from="E" to="I" rate="1/(dexposed/365.2425)" />
   <transition from="I" to="R" rate="1/(d/365.2425)" />
  </transition.matrix>
</TB.progression>

In addition to making disease duration dependent on SES, we also make infectivity depend on SES:

<TB.infectivity>
<!-- infectivity depends on SES (low SES: generally less healthy)-->
 <TB.parameter SES.stage="low"  name="infc" value="1." /> 
 <TB.parameter SES.stage="high" name="infc" value="0.8" /> 
 <infectivity.matrix Mtb-strain="drugsens">
  <infectivity stage="I" value="infc" />
 </infectivity.matrix>
</TB.infectivity>

Transmission needs to be modified as this is now the transition from S->E:

    <TB.transmission>
    <TB.parameter name="bc" value="0.4" />
      <transmission.matrix Mtb-strain="drugsens">
        <transition from="S" to="E" rate="bc" />
      </transmission.matrix>
    </TB.transmission>

An SEIR model with two SES states and counting disease incidence

Counting the accumulated incidence during a year can be accomplished by adding a disease state ending in “count” e.g. Icount.

This requires modifications to the specification of the SEIR model with two SES states. First, define the new Icount stage:

<TB.stages>
 <stage name="S" />
 <stage name="E" />
 <stage name="I" />
 <!-- add Icount -->
 <stage name="Icount" />
 <stage name="R" />
</TB.stages>

Then, add a transition from E to Icount:

<transition.matrix>
 <transition from="E" to="I" rate="1/(dexposed/365.2425)" />
 <!-- add transition from E to Icount -->
 <transition from="E" to="Icount" rate="1/(dexposed/365.2425)" />
 <transition from="I" to="R" rate="1/(d/365.2425)" />
</transition.matrix>

A TB and HIV model for South Africa (ZAF)

The simulation will be run from 1900 thru 2021 using the ode23 integration algorithm with atol=0 and rtol=3e-4 and min.value.for.state.var=-0.03; UNPOP data will be used for population age composition and death rates:

<simulation from.year="1900" thru.year="2021" dt="0.5">
 <options>
  <numerical.integration method="ode23" atol="0" rtol="3e-4" min.value.for.state.var="-0.03"/>
 </options>
 <demography country.code="ignored" rescale.population="2050">
  <from.data>
   <population file="data/demographics.csv"/>
   <birthrate from.population.data="true"/>
   <mortality file="data/deathrates.csv"/>
  </from.data>
 </demography>
 <contact.matrix file="data/all_contacts_2021.txt"/>
</simulation>

Generate output halfway through the year for age groups 0-14, 15-39, 40-99 and 0-99 ; generate flows output for TB incidence, transmission, progression and treatment and for HIV incidence, progression and treatment:

<output>
 <detailed.output years="c(2000, 2010, 2011, 2019, 2020)+0.5" age.group.lower.limits="c(0,15,40)">
  <flows dim="TB" incidence="true" transmission="true" progression="true" treatment="true"/>
  <flows dim="HIV" incidence="true" progression="true" treatment="true"/>
  <flows dim="VXa"/>
  <flows dim="RISK"/>
 </detailed.output>
</output>

Use 1-year age groups:

  <ages lower.limits="c(0:80,90)"/>

Use two SES strata: low and high

<SES>
 <SES.stages>
  <stage name="low" fraction.at.birth="0.4"/>
  <stage name="high" fraction.at.birth="0.6"/>
 </SES.stages>
</SES>

Use the following HIV stages with u for undiagnosed, d for diagnosed, n for not virally suppressed, s for virally suppressed and HIVdead for death due to HIV ; 1 and 2 indicate first and second phase in a stage and correspond to lower CD4 cell count in the higher number stages:

 <HIV.stages>
  <stage name="HIV-" fraction.at.birth="1"/>
  <stage name="HIVu1"/>
  <stage name="HIVu2"/>
  <stage name="HIVd1"/>
  <stage name="HIVd2"/>
  <stage name="ARTn1"/>
  <stage name="ARTn2"/>
  <stage name="ARTs1"/>
  <stage name="ARTs2"/>
  <stage name="HIVdead"/>
 </HIV.stages>

As the fraction at birth for HIV- equals 1, we need to specify HIV incidence where file specifies a tab-delimited file with incidence data.

<HIV.incidence>
 <incidence.data file="data/HIV-incidence-2020-aim_med.txt" times="1980,2051" values="lambdaH,lambdaH" proportions="false" denominator="susc"/>
</HIV.incidence>

lambdaH is a constant specified under <HIV.progression><HIV.parameter>

The incidence data should be in the following format:

YEAR country dim from to TB 0 5 10 15
1980 ZAF HIV HIV- HIVu1 NA 0 0 0 0
1981 ZAF HIV HIV- HIVu1 NA 0 0 0 0
1982 ZAF HIV HIV- HIVu1 NA 0 0 0 0
1983 ZAF HIV HIV- HIVu1 NA 4.92E-05 0 0 0.000159
1984 ZAF HIV HIV- HIVu1 NA 7.44E-05 0 0 0.000164
1985 ZAF HIV HIV- HIVu1 NA 8.39E-05 0 0 0.000138

(age groups from 20 and year from 1986 omitted for readability)

With proportions=“false” the incidence files should contain incidence by year and age group.
With proportions=“true” the numbers in the incidence files are interpreted as proportions by year and age group where the proportions should add to 1.

In both cases, the denominator may either be “susc” or “all”.
The susceptible state is derived from the “from” column of the incidence files.
Note that specifying “all” combined with a small fraction of susceptibles (e.g. 0.2) leads to a multiplication factor of e.g. 5 for the incidence rate which may increase instability of the simulation.
The maximum multiplication factor equals 10.

A limit of 50 is imposed on the age multiplier used in the implementation of incidence files with proportions=“true” as large multipliers could lead to an attempt to force incidence in age groups with very small numbers of individuals.

HIV incidence in the 0 thru 4 age groups is by default concentrated in the newborns (to simulate vertical transmission) which means that the specified incidence for the 0-4 age group is multiplied by 5 and applied to newborns. To not use this option, specify HIV incidence files using:

YEAR country dim from to TB 0 1 5 10 15 20
1980 ZAF HIV HIV- HIVu1 NA 0 0 0 0 0 0
1981 ZAF HIV HIV- HIVu1 NA 0 0 0 0 0 0
1982 ZAF HIV HIV- HIVu1 NA 0.001 0.0003 0 0 0.0003 0.0006

The <transition matrix> defines the rates of state transitions which are determined by the <HIV.parameter> values.
Age dependency of <HIV.parameter>`s (if any) is taken into account automatically.

<transition.matrix>
 <transition from="HIVu1" to="HIVu2" rate="gammaH"/>
 <transition from="HIVd1" to="HIVd2" rate="gammaH"/>
 <transition from="ARTn1" to="ARTn2" rate="gammaH*0.5"/>
 <transition from="ARTs1" to="ARTn1" rate="piH"/>
 <transition from="ARTs2" to="ARTn2" rate="piH"/>
 <transition from="ARTn1" to="HIVd1" rate="betaH"/>
 <transition from="ARTn2" to="HIVd2" rate="betaH"/>
</transition.matrix>

In addition to (automatic) progression, it is also possible to ‘force’ state transitions by using <treatment matrices>.
Each <treatment.matrix> defines HIV parameter dependent transition rates and a time dependent multiplier, for instance:

<treatment.matrix name="diag">
 <transition from="HIVu1" to="HIVd1" rate="j5*epsilonH"/>
 <transition from="HIVu2" to="HIVd2" rate="j5*epsilonH"/>
 <multiplier name="mul" times="2003,2010,2019" values="0,epsilonHmul2010,1"/>
</treatment.matrix>
<treatment.matrix name="treat">
 <transition from="HIVd1" to="ARTn1" rate="j6*alphaH"/>
 <transition from="HIVd2" to="ARTn2" rate="j6*alphaH"/>
<multiplier name="mul" times="2003,2010,2019" values="0,alphaHmul2010,1"/>
</treatment.matrix>
<treatment.matrix name="supp">
 <transition from="ARTn1" to="ARTs1" rate="j7*phiH"/>
 <transition from="ARTn2" to="ARTs2" rate="j7*phiH"/>
 <multiplier name="mul" times="2003,2010,2019" values="0,phiHmul2010,1"/>
</treatment.matrix>
  <treatment.matrix name="HIVARTdead">
    <transition from="HIVu1" to="HIVdead" rate="muH1"/>
    <transition from="HIVu2" to="HIVdead" rate="muH2"/>
    <transition from="HIVd1" to="HIVdead" rate="muH1"/>
    <transition from="HIVd2" to="HIVdead" rate="muH2"/>
    <transition from="ARTn1" to="HIVdead" rate="muH1*0.2"/>
    <transition from="ARTn2" to="HIVdead" rate="muH2*0.2"/>
    <transition from="ARTs1" to="HIVdead" rate="muH1*0.2*0.32"/>
    <transition from="ARTs2" to="HIVdead" rate="muH2*0.2*0.32"/>
  </treatment.matrix>
</HIV.progression>

In the treatment matrices above, we move subjects from undiagnosed (u1, u2) to diagnosed (d1, d2) using the diag treatment matrix, from diagnosed (d1,d2) to ART (not suppressed ; ARTn1, ARTn2) using the treat matrix and from ARTn1 and ARTn2 to ARTs1 and ARTs2 using the supp matrix. Dropout (ARTn1/2 to HIVd1/2) is defined in the standard transition matrix as is failure of ART (ARTs1/2 to ARTn1/2).

Contact matrices are balanced yearly to ensure matched numbers of contacts between ego and alter age groups. The contacts matrix M is updated using the following R function (where parms$contacts$MplustM is equal to M + t(M) with M the contacts matrix in the format above):

update.contact.matrix=function(parms, alive.pop){
  n = length(alive.pop)
  A = matrix(alive.pop,n,n)
  M = as.matrix((t(parms$contacts$MplustM  *  alive.pop) ) / (A+t(A)))
  M[is.nan(M)]=0.
  M
}

The minimum contents of the element is:

  <VXa>
   <stages>
    <stage name="NA" fraction.at.birth="1.0"/>
   </stages>
  </VXa>

In the example above the dimension is not used as all are in the “NA” state. Note that any name for this state would be valid.

SES

A usual definition of the SES dimension:

  <SES>
    <SES.stages>
      <stage name="low" fraction.at.birth="0.4"/>
      <stage name="high" fraction.at.birth="0.6"/>
    </SES.stages>
  </SES>

which of course means that 40% of the population has a low SES and 60% a high SES.

To not use SES specify:

  <SES>
    <SES.stages>
      <stage name="NA" fraction.at.birth="1.0"/>
    </SES.stages>
  </SES>

TB

Apart from age, the states within each dimension are defined by the user.

Parameters defined within a dimension determine the transition between states within that dimension.

To allow e.g. TB progression to depend on vaccination state (or HIV state), it is possible to make TB parameters dependent on VXa state. For instance:

    <TB.transmission>
      <age.groups>
        <age.group name="A0"/>
        <age.group name="A15"/>
      </age.groups>
      <TB.parameter VXa.stage="never" name="pV" value="0"/>
      <TB.parameter VXa.stage="prev1" name="pV" value="0"/>
      <TB.parameter VXa.stage="prev2" name="pV" value="0"/>
      <TB.parameter VXa.stage="prev3" name="pV" value="0"/>
      <TB.parameter VXa.stage="waned" name="pV" value="0"/>
      <TB.parameter VXa.stage="vac1" name="pV" value="0.45"/>
      <TB.parameter VXa.stage="vac2" name="pV" value="0.45"/>
      <TB.parameter VXa.stage="vac3" name="pV" value="0.45"/>
      <TB.parameter VXa.stage="recvcount" name="pV" value="0"/>
      <TB.parameter SES.stage="low" name="pE" value="0"/>
      <TB.parameter SES.stage="high" name="pE" value="0.3567966523385633"/>

The XML fragment above illustrates that the TB parameters that determine transmission may depend on VXa stage i.e. pV (protection due to vaccination pV depends on VXa stage).
In the example above the pE parameter is defined to depend on SES stage.

Parameters may also depend on age group:

      <TB.parameter name="sage" age.group="A0" value="1"/>
      <TB.parameter name="sage" age.group="A15" value="0.655943563330546"/>

The following parameter dependencies may be defined:

TB.parameter can depend on VXa.stage, SES.stage, RISK.stage, HIV.stage and age.group

HIV.parameter can depend on age.group

RISK.parameter can depend on age.group

SES.parameter can depend on age.group

VXa.parameter can depend on age.group and TB.stage (to make waning dependent on TB stage)
